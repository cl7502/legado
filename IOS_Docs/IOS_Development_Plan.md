# Legado iOS 版本开发计划 v2.0（GSD 强化版）

> **文档目的**：在 v1.0 基础上，吸收 GSD 审查建议，重点强化 **Rhino API 深度模拟**、**解析上下文管理**及**内容净化引擎**，确保 100% 兼容 Android 书源逻辑。

---

## 📋 核心修订说明（vs v1.0）

1.  **Rhino 仿真升级**：将 JS 引擎开发周期由 2 周延长至 4 周，新增 Crypto、Encoding、Time 等 50+ Java 助手方法映射。
2.  **新增净化引擎**：独立规划“内容净化模块”，专门处理正文广告剔除与正则替换。
3.  **引入解析上下文（Context）**：所有规则执行器强制要求 `ExecutionScope` 对象，支持变量在多级解析中透传。
4.  **性能与稳定性保障**：新增 `JSContext` 池化管理、1000+ 书源压力测试、iOS 后台下载任务（BackgroundTasks）专项。

---

## 🚀 阶段 2：深度数据模型与上下文设计（1 周）

### 阶段目标
设计支持复杂解析流转的数据结构。

### 关键任务
1.  **解析上下文模型 (`AnalyzeContext`)**：
    - 设计 `source` (书源), `result` (上级结果), `baseUrl`, `cookie`, `variables` (自定义变量) 的容器。
2.  **内容净化规则模型 (`ReplaceRule`)**：
    - 完整对标 Android 版的净化规则字段。
3.  **书源模型增强**：
    - 增加 `group` 索引、`customOrder` 逻辑支持。

---

## 🚀 阶段 3：Rhino API 深度模拟与 JS 引擎（4 周）

### 阶段目标
解决“书源逻辑不兼容”的核心瓶颈。

### 核心攻坚任务
1.  **JSJavaHelper 模块化重构**：
    - **Network**: 实现 `ajax` 同步封装（使用信号量）。
    - **Crypto**: 实现 `md5`, `sha1`, `base64` 等原生 Swift 映射。
    - **Encoding**: 实现 `encodeHtml`, `decodeHtml`, `urlEncode/Decode`。
    - **Utils**: 实现 `getNetworkTime`, `log`, `toast`。
2.  **JSContext 池化管理**：
    - 为了避免频繁创建销毁导致的内存碎片，实现上下文复用池。
3.  **同步/异步转换攻坚**：
    - 确保 JS 环境下的同步调用不会阻塞 iOS 主线程。

---

## 🚀 阶段 4：规则系统与解析上下文流转（2 周）

### 阶段目标
实现“多级跳转、变量透传”的解析能力。

### 关键任务
1.  **RuleExecutor 重构**：
    - 执行器必须接收 `AnalyzeContext`。
    - 支持 `@get` / `@put` 动态变量提取。
2.  **多级解析链支持**：
    - 处理 `Search -> Detail -> TOC -> Content` 的完整闭环数据流。

---

## 🚀 阶段 5：内容净化引擎与正文处理（1 周）

### 阶段目标
确保阅读体验“干净无广告”。

### 关键任务
1.  **正则净化引擎**：
    - 实现高效的批量正则替换逻辑。
2.  **CSS 节点剔除**：
    - 支持规则中定义的“待删除”节点处理。
3.  **分章节缓存策略**：
    - 实现净化后的正文持久化存储。

---

## 🚀 阶段 6：增强型网络层与后台任务（1 周）

### 阶段目标
突破 iOS 系统对网络和后台的限制。

### 关键任务
1.  **BackgroundTasks 集成**：
    - 实现 `BGAppRefreshTask` 以支持后台自动更新书源。
    - 实现 `URLSessionConfiguration.background` 以支持离线书籍下载。
2.  **动态 Header 计算**：
    - 支持在 JS 环境中动态计算签名 Header。

---

## 🚀 阶段 7：数据库层与大规模数据优化（1 周）

### 阶段目标
支撑 1000+ 书源不卡顿。

### 关键任务
1.  **GRDB 全文索引**：
    - 针对书名、作者、书源名称建立索引。
2.  **懒加载与分页查询**：
    - 优化书源管理页面的加载性能。

---

## 🚀 阶段 10：极限压力测试与发布（2 周）

### 阶段目标
确保 100% 兼容性目标达成。

### 极限任务
1.  **1000+ 书源兼容性大考**：
    - 自动化运行 Top 200 书源的搜索任务，对比 Android 返回结果。
2.  **内存泄露/OOM 监控**：
    - 在 100MB 内存红线下运行极端解析脚本。
3.  **App Store 审核预演**：
    - 准备“用户自建书源”模式的演示视频与申诉文档。
