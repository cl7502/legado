## 二、核心模块说明

### 2.1 Database（DatabaseManager.swift）

**职责**：管理 SQLite 数据库生命周期和 schema 迁移。

- 使用 GRDB 的 `DatabaseMigrator` 进行版本化迁移，每次 App 启动时检查并执行尚未运行的迁移步骤。
- 当前共约 10 个迁移版本，覆盖 BookSource/Book/Chapter/Bookmark/Highlight 等表。
- 对外暴露 `DatabaseManager.shared`（单例），通过 `DatabaseQueue` 同步/异步读写。
- 新增模型字段**必须**在此文件注册新的 `migrator.registerMigration("vN-...")` 迁移，否则 SQLite 写入会报 error 1（列不存在）。

**已知问题**：`DatabaseManager.shared` 目前在 `@MainActor` 上同步初始化，10 次迁移状态检查阻塞主线程，导致冷启动延迟 5+ 秒。待优化方向：迁移移至后台队列，初始化完成后再渲染主界面。

### 2.2 Network（NetworkManager + HeadlessWebViewLoader）

**NetworkManager.swift**
- 封装 Alamofire，支持自定义 Header、超时、重试。
- 通过 `CookieManager` 管理每个书源域名的 Cookie 持久化。
- `EncodingHelper` 处理 GBK/GB2312 等非 UTF-8 编码的响应。
- `LegadoInterceptor` 实现请求拦截（自动附加 Referer/Cookie 等）。

**HeadlessWebViewLoader.swift**
- 基于 WKWebView 无头模式，用于加载需要 JS 渲染的动态页面。
- 等待页面 `document.readyState === 'complete'` 后提取 HTML。
- 超时兜底：默认 15 秒后强制返回当前 DOM。

### 2.3 Rule Engine（RuleParser + RuleExecutor + AnalyzeContext）

这是整个书源兼容性的核心。

**RuleParser.swift**
- 解析规则字符串，识别规则类型前缀：
  - 无前缀 / `@@`：默认（CSS 选择器或直接文本）
  - `@XPath:`：XPath 规则，转发给 LibXMLXPath
  - `@Json:` / `$.`：JSONPath，转发给 JSONPathEngine
  - `:`：正则表达式
  - `<js>...</js>`：JavaScript 代码块
- 支持 `||` 连接的多规则链，支持 `##replaceFirst##` 和 `##replace##` 替换。
- 支持 `###` 分割字符串为多值数组。
- 支持 Legado 数字下标语法：如 `a.0@href`（取第 0 个 `a` 元素的 `href` 属性）。

**RuleExecutor.swift**
- 接受 `AnalyzeContext`（含 HTML 源码或 JSON 数据），执行规则链，返回结果字符串或数组。
- 多规则链从左到右依次执行，前一步结果作为下一步输入。
- 调用链：`RuleExecutor` → `HTMLParser`（CSS/XPath）/ `JSONPathEngine`（JSONPath）/ `LegadoJSEngine`（JS）。

**AnalyzeContext.swift**
- 保存当前解析上下文：原始 HTML/JSON 字符串、当前元素节点、书源变量（`@put`/`@get`）。
- 变量存储用嵌套深度计数防止无限递归（`@put`/`@get` 深度检查）。

### 2.4 HTML 解析（HTMLParser）

- 基于 SwiftSoup 实现 CSS 选择器解析。
- 基于 LibXMLXPath 实现 XPath 解析。
- 支持 `@attr` 提取属性、`text()` 提取文本、`html()` 提取 innerHTML。
- 支持 `ElementWrapper`，对数组元素逐个应用子规则。

### 2.5 JSONPath（JSONPathEngine.swift）

- 自实现 JSONPath 引擎，支持 `$`, `..`（递归下降）, `[*]`, `[n]` 等标准语法。
- 解析 JSON 字符串后返回匹配节点数组或单值。
- 支持 `@Json:` 前缀和 `$.` 开头两种触发方式。

### 2.6 JS Bridge（LegadoJSEngine + JSJavaHelper）

**LegadoJSEngine.swift**
- 基于 `JavaScriptCore` 提供 JS 执行环境。
- 将 `JSJavaHelper` 实例以 `java` 名称注入 JS 上下文，兼容 Android Legado JS 书源中 `java.xxx()` 调用约定。
- 支持同步执行（短脚本）和异步回调队列（`syncCallbackQueue`，优先级已修正）。

**JSJavaHelper.swift**
- 实现 Android `java` 对象的 iOS 兼容层，已实现方法包括：
  - `toast(msg)` / `getString(key)` / `getStringArray(key)`
  - `removeCookie(url)` / `getCookie(url, key)`
  - `rsaEncrypt(data, key)` / `aesEncrypt(data, key, iv)`
  - `htmlDecode(str)` / `hexDecodeToString(hex)`
  - `timeFormat(timestamp)` — 自动识别秒/毫秒时间戳
  - `getElements(rule, src)` — 返回元素列表供 JS 进一步处理

### 2.7 TTS（TTSManager）

- 封装 `AVSpeechSynthesizer`，管理朗读状态（播放/暂停/停止）。
- 支持语速调节（`AVSpeechUtterance.rate`，范围 0.5×～2.0×）。
- 支持 iOS 系统内置多语言发音人（`AVSpeechSynthesisVoice`）。
- 支持定时停止：设定分钟数后自动调用 `stop()`。
- 朗读完当前段落自动请求下一段，保持连续朗读。

### 2.8 阅读器（ReaderView + ReaderViewModel）

**ReaderViewModel.swift**
- 持有书源引用、当前书籍/章节状态、分页数据。
- 通过 `BookContentParser` 获取章节正文（先查本地缓存，缓存未命中则网络请求）。
- 管理并发预缓存（`BackgroundDownloadManager`）：预缓存下一 N 章。
- 维护书签、高亮列表（GRDB 读写）。
- 维护 `SourceSelectionViewModel` 供换源功能使用。

**ReaderView.swift / SimulationPagingView.swift**
- `ReaderView`：主阅读容器，管理工具栏显示/隐藏、Header/Footer 布局。
- `SimulationPagingView`：基于 TextKit 2 的分页渲染视图，将正文字符串分割为若干 `ReaderPageView` 页面。
- 分页算法：依据字体大小、行距、屏幕尺寸计算每页可容纳字数，精确分割。

### 3.2 阅读器分页流程

```
ReaderViewModel.loadChapter(index)
      │
  查 DatabaseManager 章节缓存
      │ 命中 → 直接使用缓存文本
      │ 未命中
      ▼
  NetworkManager.request(chapterUrl)
      │
  BookContentParser.parse(html, contentRule)
      │   ├─ RuleExecutor（CSS/XPath/JSONPath/JS）
      │   └─ ContentProcessor（图片替换/HTML 清理）
      │
  写入 DatabaseManager 章节缓存
      │
  SimulationPagingView 分页渲染（TextKit 2）
      │

```

### 3.3 规则执行流程

```
原始规则字符串
      │
RuleParser.parse()
      │ 识别类型
      ├─ CSS/默认  → SwiftSoup.select()
      ├─ @XPath:   → LibXMLXPath.evaluate()
      ├─ @Json:    → JSONPathEngine.query()
      ├─ 正则 :    → NSRegularExpression
      └─ <js>      → LegadoJSEngine.evaluate()
                        │
                    JSJavaHelper（java.xxx() 兼容层）
                        │
                    JavaScriptCore 执行
      │
  多规则链（||）循环 → 上一步结果作为下一步输入
      │
  ## 替换/### 分割（后处理）
      │
最终结果（String 或 [String]）
```

## 六、已知问题与技术债务

### 6.1 冷启动延迟（高优先级）

**根因**：`DatabaseManager.shared` 是 `@MainActor` 上的同步单例，初始化时运行 GRDB `DatabaseMigrator` 的所有迁移检查（约 10 次），直接阻塞主线程。

**表现**：首次启动（或重装后）UI 出现约 5 秒以上的白屏或无响应。

**修复方向**：
1. 将迁移执行移至后台队列（`DispatchQueue.global()`或 Swift structured concurrency）。
2. 在迁移完成前展示启动屏（Splash Screen）或骨架屏。
3. 改用 `async` 初始化，`@MainActor` 只负责最终 publish 结果。

### 6.2 其他技术债务

| 问题 | 位置 | 描述 |
|------|------|------|
| 章节缓存无失效策略 | DatabaseManager | 缓存只增不减，长期使用后数据库体积膨胀 |
| 规则引擎无单元测试 | Core/Engine/ | 没有自动化测试，回归风险高 |
| HeadlessWebView 内存泄漏 | HeadlessWebViewLoader | 并发多个 WKWebView 未及时释放 |
| 搜索结果无分页 | SearchViewModel | 全量加载，书源多时内存压力大 |
| iCloud 同步未实现 | — | 书架和进度不跨设备同步 |
