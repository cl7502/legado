### 2. Android 版本代码分析（理论验证）

#### 2.1 JavaScript 引擎分析

**发现**：
- Android 版本使用 `RhinoScriptEngine`（基于 Mozilla Rhino）
- 核心文件：`modules/rhino/src/main/java/com/script/rhino/RhinoScriptEngine.kt`
- 关键特性：
  - 支持 ES6 语法
  - 支持 JavaScript 协程（suspend 函数）
  - 支持 Java 对象桥接
  - 支持脚本编译和缓存

**关键方法**：
```kotlin
object RhinoScriptEngine {
    fun eval(js: String, bindingsConfig: ScriptBindings.() -> Unit = {}): Any?
    fun compile(script: String): CompiledScript
    fun getRuntimeScope(context: ScriptContext): Scriptable
}
```

#### 2.2 规则系统分析

**发现**：
- 核心类：`AnalyzeRule`（`io/legado/app/model/analyzeRule/AnalyzeRule.kt`）
- 支持 5 种规则类型：
  - `Mode.Default`: 默认规则（CSS 选择器）
  - `Mode.XPath`: XPath 规则
  - `Mode.Json`: JSONPath 规则
  - `Mode.Js`: JavaScript 规则
  - `Mode.Regex`: 正则规则

**规则语法**：
```kotlin
// 默认规则
@@class.p1@text
@CSS:class.p1@text

// XPath 规则
@XPath://div[@class="title"]/text()

// JSON 规则
@Json:$.data.list[*].title

// JavaScript 规则
<js>result.map(item => item.title)</js>

// 正则规则
@Regex:<title>(.*?)</title>
```

#### 2.3 Rhino API 分析

**发现**：
- Rhino 提供了丰富的 Java 互操作 API
- 关键 API：
  - `java.ajax(url)`: 网络请求
  - `java.put(key, value)`: 保存变量
  - `java.get(key)`: 获取变量
  - `java.log(message)`: 日志输出
  - `result`: 解析结果
  - `baseUrl`: 基础 URL
  - `source`: 书源对象

**使用示例**：
```javascript
// 在书源规则中使用
java.ajax(baseUrl + "/search?q=" + key)
java.put("searchResult", result)
var cached = java.get("searchResult")
```

## 📊 理论验证结果

### JavaScriptCore 基础功能

**理论分析**：
- ✅ JavaScriptCore 是 iOS 内置引擎，无需额外依赖
- ✅ 支持完整的 JavaScript 语法（ES6+）
- ✅ 支持对象桥接（`@objc` + `JSExport`）
- ✅ 支持异常处理（`exceptionHandler`）
- ✅ 性能优秀，内存占用低

**预期兼容性**：100%

---

### Rhino API 兼容性

**理论分析**：
- ⚠️ JavaScriptCore 不支持 Java 对象的自动桥接
- ⚠️ 需要手动实现所有 Rhino API
- ✅ 可以通过 `JSExport` 协议实现 API 映射
- ✅ 可以通过 `Context.javaToJS` 实现对象转换

**需要实现的 API**：
- `java.ajax(url, method)` - 网络请求
- `java.put(key, value)` - 保存变量
- `java.get(key)` - 获取变量
- `java.log(message)` - 日志输出
- `result` - 解析结果
- `baseUrl` - 基础 URL
- `source` - 书源对象

**预期兼容性**：90-95%

**潜在问题**：
1. 异步网络请求需要特殊处理（同步化）
2. 对象桥接可能需要手动转换
3. 某些 Rhino 特有特性可能不支持

---

### 规则系统兼容性

**理论分析**：
- ✅ 规则语法简单，易于实现
- ✅ 规则类型明确，易于解析
- ✅ 规则执行逻辑清晰

**规则类型支持**：
- ✅ 默认规则（CSS）：SwiftSoup 支持
- ✅ XPath 规则：SwiftSoup 支持
- ✅ JSON 规则：需要实现 JSONPath
- ✅ 正则规则：NSRegularExpression 支持
- ✅ JavaScript 规则：JavaScriptCore 支持

**预期兼容性**：95-100%

**潜在问题**：
1. JSONPath 需要额外实现或使用第三方库
2. 复杂嵌套规则可能需要特殊处理

---

### HTML 解析兼容性

**理论分析**：
- ✅ SwiftSoup 是 JSoup 的 Swift 移植版本
- ✅ API 高度兼容
- ✅ 支持大部分 JSoup 功能

**解析方法支持**：
- ✅ CSS 选择器：SwiftSoup 原生支持
- ✅ XPath：SwiftSoup 支持
- ✅ 正则表达式：NSRegularExpression 支持
- ⚠️ JSONPath：需要额外实现

**预期兼容性**：90-95%

**潜在问题**：
1. 某些高级 CSS 选择器可能不完全支持
2. XPath 语法可能有细微差异

## 📋 技术方案确认

### 最终技术方案

✅ **确认使用纯 iOS 原生开发**

**技术栈**：
```
语言: Swift 5.9+
UI框架: SwiftUI (iOS 15+)
架构模式: MVVM + Combine
数据库: GRDB.swift
网络请求: URLSession + Alamofire
JavaScript引擎: JavaScriptCore (iOS 内置)
HTML解析: SwiftSoup
TTS引擎: AVSpeechSynthesizer (iOS原生)
```

### 方案优势

1. ✅ 开发速度最快（4-5 个月）
2. ✅ 技术风险最低（纯原生开发）
3. ✅ 团队要求简单（仅需 iOS 开发者）
4. ✅ 维护成本低（无跨平台依赖）
5. ✅ 快速迭代（响应更快）

### 关键决策

1. ✅ 使用 JavaScriptCore（而非 QuickJS）
   - iOS 内置，无需额外依赖
   - 性能优秀
   - 社区支持好

2. ✅ 使用 SwiftSoup（而非其他 HTML 解析库）
   - JSoup 的 Swift 移植版本
   - API 高度兼容
   - 社区活跃

3. ✅ 使用 GRDB.swift（而非 SQLite.swift）
   - 性能更好
   - API 更现代
   - 支持 Combine

4. ✅ 使用 Alamofire（而非纯 URLSession）
   - 功能更完整
   - 支持拦截器
   - 更好的 Cookie 管理
